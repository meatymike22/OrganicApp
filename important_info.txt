2. WHAT ROOTIFY IS + THE RULES IT FOLLOWS
===============================================================================

A consumer site/app: search or scan a grocery (or other consumer) product and
see its ingredients, nutrition, organic and Non-GMO certifications, recalls and
regulatory actions, who owns the brand, and supply-chain information. Every
fact links to a primary source with the date it was read.

Rules that shape everything (don't break these without thinking hard):
  - Every record has a sourceUrl and a dataPulledDate. No source = no record.
  - NO scores, ratings or verdicts. Report facts, dated and sourced.
  - "Not found" is a valid answer and is shown as such.
  - Recalls: always show the recall's product description, never a bare count.
    A recall lives on the page of the company that issued it. Product pages
    link to it only when there is evidence it is that product/brand (barcode,
    brand named in the notice, etc.), and the page says what that evidence is.
    A recall from a supplier/co-packer/retailer is labelled as such.
  - Estimates (AI or keyword categories) are labelled "(estimated)".
  - Voice: state the record and the date, then stop. Written for consumers.
  - Verification is done by automated AI review + user-reported errors (no
    human review step, decided Sept 2026). This must be disclosed in the legal
    pages (see compliance\).
  - Don't publicly name the family; "small family business" only.
  - Subscriptions are the only consumer revenue; no ads; recalls free for all.

4. RUNNING THINGS DAY TO DAY  (PowerShell, in the project folder)
===============================================================================

    cd D:\AppDev\OrganicApp\mcelroys-trust-profile
    npm install                    first time, or after package.json changes
    npx prisma generate            ALWAYS after a schema change, before scripts
    npm run dev                    website at http://localhost:3000
    npx tsc --noEmit               check the code for type errors without running it
    npm run build                  full production build (what Vercel will run)

Schema change (add/change a field or table):
    1. edit prisma\schema.prisma
    2. npx prisma migrate dev --name short_description
    3. npx prisma generate
    4. restart npm run dev

Scripts:   npx tsx scripts\<name>.ts [options]
    Almost every script is a DRY RUN by default (reads, writes a plan/log, changes
    nothing). Add --live to actually write. ALWAYS dry run first and read the log
    in logs\ before --live. Many have --undo <applied-file>.

Next.js note: this project uses a new Next.js (16) with breaking changes. Its own
docs are in node_modules\next\dist\docs\ — check there before following an
older tutorial.

Git (from D:\AppDev\OrganicApp):
    git status
    git add -A                     .gitignore keeps .env, logs\, data\, node_modules out
    git commit -m "what changed"
    Check `git status` never lists .env before committing.

7. SAFE WAYS TO CHANGE DATA + HOW TO UNDO
===============================================================================

  - Dry run first, read the log, then --live. Keep the logs\ files: the
    "applied" JSON files are what --undo needs.
  - Before a big manual change, copy the affected rows into the review_backup
    schema first, e.g.:
        CREATE TABLE review_backup.my_change_2026_10_01 AS
        SELECT * FROM "Company" WHERE ... ;
  - Deletes: do them in the Supabase SQL Editor, children before parents
    (ProductIngredient / NutritionFacts / RegulatoryActionLink → Product → Company).
    Prisma Studio silently fails on deletes and array edits — use SQL.
  - Scripts that delete-then-recreate must wrap both in prisma.$transaction().
  - Never set reviewerId from a script (that field means a person reviewed it).
  - Supabase also keeps daily backups (Pro plan): Dashboard > Database > Backups.

review_backup tables still kept (undo history):
    category_assignments    every category change (undo categories by run_label)
    vetting_assignments     every automated vetting change
    ai_vetting_proposals    AI vetting suggestions
    merged_companies        which companies were merged into which
    brand_owner_review      brand-owner decisions
    deleted_companies / deleted_products / deleted_ingredients /
    deleted_nutrition / deleted_product_ingredients   copies of deleted rows
  category_assignments, vetting_assignments and ai_vetting_proposals can be
  dropped once you trust the categories and vetting. Keep merged_companies and
  deleted_* longer (they're the only record of what was removed).

10. GOTCHAS THAT COST TIME BEFORE
===============================================================================

  - "Unknown argument" / missing fields from Prisma = forgot `npx prisma generate`.
  - P1001 can't reach database = using the direct connection string; use the
    session pooler (section 1). If it suddenly fails everywhere, check whether the
    Supabase project is paused (free tier pauses after ~1 week idle) or over its
    disk/compute limits in the dashboard.
  - "Transaction API error ... timeout 5000 ms" = Prisma's default transaction limit;
    pass { maxWait: 30000, timeout: 120000 } and use smaller batches (see
    apply-ai-categories.ts).
  - array_append doesn't de-duplicate: use ARRAY(SELECT DISTINCT unnest(col)).
  - Recall firms are legal entities (e.g. "Campbell Soup Supply Co."); one recall
    can mention sibling brands. Don't attach a recall to a whole parent company.
  - Windows line endings: files are a mix of CRLF and LF; either works.
  - npx/npm "running scripts is disabled": run PowerShell as Administrator once:
    Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
  - Prisma 7: the database URL is read in prisma.config.ts (not schema.prisma), and
    PrismaClient needs the PrismaPg adapter (see src\lib\prisma.ts).
  - New ids must default in the database: @default(dbgenerated("gen_random_uuid()")),
    so rows inserted by raw SQL get ids too.
  - USDA Organic Integrity exports download as .csv but are really .xlsx — rename.
  - .env must be named exactly .env (not .env.txt), next to package.json.
  - Open Food Facts brand text is typed by volunteers — expect wrong brands.
    That's why companies get "held" until there's evidence.

11. USEFUL SQL  (Supabase > SQL Editor)
===============================================================================

-- Find a company
SELECT id, "legalName", "dbaNames", "vettingStatus", "parentCompanyId"
FROM "Company" WHERE "legalName" ILIKE '%nature''s path%';

-- A company's products
SELECT id, name, upc, category, "categorySource" FROM "Product"
WHERE "companyId" = 'paste-company-uuid' ORDER BY name;

-- Find a product by barcode
SELECT p.id, p.name, c."legalName" FROM "Product" p
JOIN "Company" c ON c.id = p."companyId" WHERE p.upc = '0123456789012';

-- Move a product to another company
UPDATE "Product" SET "companyId" = 'new-company-uuid' WHERE id = 'product-uuid';

-- Set a parent company
UPDATE "Company" SET "parentCompanyId" = 'parent-uuid' WHERE id = 'child-uuid';

-- Add a brand name without duplicates
UPDATE "Company" SET "dbaNames" = ARRAY(SELECT DISTINCT unnest("dbaNames" || ARRAY['New Brand'])) WHERE id = 'company-uuid';

-- Undo an AI category run (run label is printed by apply-ai-categories.ts)
UPDATE "Product" p SET category = b.old_category, "categorySource" = b.old_source
FROM review_backup.category_assignments b
WHERE b.run_label = '<label>' AND p.id = b.product_id
  AND p.category IS NOT DISTINCT FROM b.new_category;

-- Delete orphaned ingredients (dry check first: change DELETE to SELECT count(*))
DELETE FROM "Ingredient" i
WHERE NOT EXISTS (SELECT 1 FROM "ProductIngredient" pi WHERE pi."ingredientId" = i.id)
  AND NOT EXISTS (SELECT 1 FROM "IngredientStudy" s WHERE s."ingredientId" = i.id);

-- Recalls/actions a company issued (RegulatoryAction."companyId" = the issuer)
SELECT id, "sourceAgency", "actionDate", "productDescription" FROM "RegulatoryAction"
WHERE "companyId" = 'company-uuid' ORDER BY "actionDate" DESC;

-- Recalls linked to a company/brand or product, and why (matchMethod:
-- barcode, brand_name, owner_brand, firm_is_brand, named_brand)
SELECT r.id, r."actionDate", r."productDescription", l."productId", l."matchMethod", l."matchedText"
FROM "RegulatoryActionLink" l JOIN "RegulatoryAction" r ON r.id = l."actionId"
WHERE l."companyId" = 'company-uuid' ORDER BY r."actionDate" DESC;
